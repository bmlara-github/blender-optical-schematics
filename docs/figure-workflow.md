# Figure versions, illumination and approval

Use one `Figures/YYYY-MM-DD-FigXX/` folder for one figure. Use the local date and the next unused consecutive figure number within that date and project. Revisions stay in that folder and end in `_vXX` before the extension; do not create new figure folders for a camera, slider or lighting revision.

Keep scripts in `python/`, scenes and Blender backups in `blender/`, metadata and validation in `json/`, notes in `md/`, logs in `txt/`, source images in `source/`, previews in `renders/`, and paired exports in `svg/`. Camera-search samples may retain their `coarse/` and `refine/` study folders. Git does not track empty folders; the example creates them when run. Reusable project code stays in `scripts/`, assets in `library/`, and the bundled tutorial in `examples/`.

1. Follow the single original paper example in the user guide. Save the fixed view as `fixed_v01.blend`, run the sampler, then save the selected compact view as `compact_v03.blend`. These suffixes illustrate revision history, not required stage numbers; use the next version for later changes.
2. Selecting a POV approves composition only. Inspect aperture visibility, panel clearance and separated branches before finishing appearance. Keep the experimental project's established POV unless a change is requested.
3. Save illumination as the next version. `workflow.finish('compact', OUT, version=4, source_version=3)` opens v03, packs images, preserves camera, geometry and approved beam materials, adds camera-relative key/fill/rim lights, and writes v04. The helper rejects overwriting existing scene versions. For new revisions use `version=5, source_version=4`.
4. Inspect the render on white. Reduce ambient/fill if flat; balance key and rim to reveal housing depth and lens edges without hiding apertures. Preserve approved translucent red envelopes and thin cores. Only use `restore_beams=True` when intentionally restoring that beam style. If the camera changes, recompute light placement and reference-panel alignment.
5. Use the library iris and pinhole. The original example images the pinhole onto the SLM with its input 4F relay. For schematic translation hardware use a minimal rail and carriage, with CCD directly on the carriage. If the lower CCD corner creates overlap, use its rear top-left housing corner as the vertical anchor and verify projected panel/component clearance. Measure the horizontal panel gap from the complete instrument silhouette.
6. Export matching lettered and unlettered SVGs with `--version 4`. Verify width 86 mm, borders 0.5 mm, proportional height, editable lettering, identical embedded render and no clipping. The optics are a raster render inside the SVG; the labels are vectors. Do not label illustrative envelopes as simulated diffraction.
7. Show the illuminated version for approval. Until approved, leave `FinalFigure/` empty for a new figure. A flat or insufficiently illuminated scene is still a working version, even if its POV is selected.
8. After explicit visual approval, run `python scripts/finalize_figure.py Figures/YYYY-MM-DD-FigXX --stage compact --version 4 --approved`. This copies the selected Blender scene and both SVGs, verifies their hashes, and records approval in `json/`. Earlier working versions remain available; an existing approved version is never silently overwritten.
9. Close application windows opened for the task after saving. Do not close unrelated user windows.

The original paper example remains the sole tutorial scene. The local 20 mm relay figure is a separate user figure and does not replace it in the guide.
