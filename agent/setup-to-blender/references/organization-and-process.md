# Organization and process contract

## Distribution

Keep the libraries, this agent, the single paper example and its optimization samples in the GitHub package, along with their supporting scripts, documentation, licenses and citations. Keep user working figures, revision history and execution logs outside the distribution. The repository ignores `Figures/`; never force-add it for publication.

Read root `AGENTS.md`, `docs/assets.json`, `docs/figure-workflow.md`, and the selected example's README before authoring. Resolve paths from the repository root. Installed agent location is not a reliable repository locator.

## Figure folders and names

Use one `Figures/YYYY-MM-DD-FigXX/` per figure, with the user's local date and next unused consecutive number for that date. Keep camera, component and lighting revisions in the same folder. Save the next unused `_vXX` suffix immediately before the file extension. Never silently overwrite a saved revision.

| Folder | Contents |
| --- | --- |
| `python/` | Reproducible figure-specific builders, `build_vXX.py` |
| `blender/` | Editable scenes and local Blender backups |
| `json/` | Setup, camera, panel, lighting, export and validation records |
| `md/` | Assumptions, instructions, revision notes and approval status |
| `txt/` | Execution logs |
| `source/` | Supplied source images and their provenance |
| `renders/` | Clean PNGs and previews |
| `svg/` | Matching lettered and unlettered exports |
| `coarse/`, `refine/` | Indexed camera candidates, settings, rankings and comparisons |
| `FinalFigure/` | Copies of explicitly approved deliverables only |

Stable README indexes, immutable input image names and indexed camera study files may keep stable filenames. Preserve existing study results when repeating a search; use a new versioned study directory. Reusable code belongs in `scripts/`; new reusable optical shapes and their metadata belong in `library/`.

## Data records

Use JSON with repository-relative or figure-relative paths, explicit units, and explicit separation of facts and assumptions. Do not fabricate measured dimensions or claim that a record is an executable schema when it is an authoring plan. Use the bundled `examples/paper-setup/layout.json` and helper outputs as concrete format references.

| Record | Required information |
| --- | --- |
| `setup_vXX.json` | Source facts and provenance; assumptions; units; component IDs and library collection mappings; transforms; beam routes; focal lengths and folded spans when known |
| `*-camera_vXX.json` | Preset and projection; camera transform; target; scale or lens; clipping; render resolution |
| `*-panels_vXX.json` | Input image, associated instrument, projected anchor and silhouette gap, aspect ratio and clearance checks |
| `*-lighting_vXX.json` | Source/output versions, camera-relative lights, material preservation choices and inspection status |
| `*-export_vXX.json` | Requested width, proportional height, border, SVG pair paths and embedded-raster disclosure |
| `validation_vXX.json` | Checks actually performed, outcomes, limitations and unresolved issues |
| `*-approval_vXX.json` | Explicit owner approval, selected version and copied final-file hashes; generated by the finalization helper |

## Process

1. Interpret the supplied setup and identify missing facts. Record assumptions before creating geometry. Reuse library instances and preserve generic lens shapes.
2. Build and save the initial version, packing image textures. Validate axes, apertures, beam continuity, source panels and unit conventions. Produce a clean preview.
3. For camera optimization, follow `docs/camera-view-search.md`. Keep optical geometry fixed, re-anchor panels at each view, render coarse then refined samples, rank and inspect them. Reject clipped or unreadable views. A finite sampler is not a global optimum. Preserve source settings and the chosen camera record.
4. Save the selected POV as a new version. Selection approves composition only. Follow `docs/scene-finishing.md` to add camera-relative illumination while preserving approved geometry and beam appearance. Save another version.
5. Export paired SVGs at 86 mm by default, or the requested width. Verify dimensions, proportional height, requested border, identical raster imagery and editable lettering. Do not describe illustrative beam envelopes as diffraction simulations.
6. Inspect the illuminated render and exports. Record only checks actually performed. Obtain explicit visual approval before finalization; do not infer it from camera selection or successful validation.
7. Run `scripts/finalize_figure.py` with the approved stage/version and `--approved`. Preserve older versions and an existing approved set. Close only task-opened application windows after saving.
8. Before preparing the distribution, run `scripts/validate_structure.py`. Exclude generated user figures and local history; retain only the designated example outputs and optimization samples.

For the paper tutorial, use `examples/paper-setup/workflow.py` and `export.py`. Default fixed/compact/illumination version numbers illustrate stages; choose subsequent unused versions for later revisions. Never treat historical `expected/` fixture filenames as the naming template for new output.
